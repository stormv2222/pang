# PLAN.md - Phase별 개발 목표

각 Phase는 독립적으로 실행 가능한 SW를 목표로 한다.
고객은 각 Phase 완료 시점에 직접 브라우저에서 실행하여 테스트한다.

---

## Phase 1. 메인 화면

**목표**: 게임을 처음 실행하면 메인 화면이 표시된다

### 구현 내용
- 게임 타이틀 "PANG" 표시
- 게임 시작 버튼
- 게임 종료 버튼

### 고객 확인 포인트
- 브라우저에서 실행하면 메인 화면이 나오는가?
- 게임 시작 버튼과 종료 버튼이 보이는가?
- 게임 시작 버튼을 누르면 화면이 전환되는가?
- 게임 종료 버튼을 누르면 종료 안내가 표시되는가?

---

## Phase 2. 게임 캔버스 및 배경

**목표**: 게임이 그려지는 캔버스가 고정 크기로 표시된다

### 구현 내용
- 메인 화면 → 게임 화면 전환
- 고정 해상도 게임 캔버스
- 만리장성 배경 (단색 또는 단순 구분)
- 바닥/천장/벽 경계 표시

### 고객 확인 포인트
- 게임 시작 후 캔버스가 올바른 크기로 표시되는가?
- 배경과 경계가 시각적으로 구분되는가?

---

## Phase 3. 플레이어 이동

**목표**: 플레이어 캐릭터가 화면에 등장하고 좌우로 움직인다

### 구현 내용
- 플레이어 캐릭터 렌더링
- 키보드 방향키(←→)로 좌우 이동
- 화면 경계에서 이동 제한

### 고객 확인 포인트
- 게임 화면에 캐릭터가 보이는가?
- 방향키로 캐릭터가 좌우로 이동하는가?
- 화면 끝에서 더 이상 이동하지 않는가?

---

## Phase 4. 와이어 발사

**목표**: 스페이스바를 누르면 와이어가 위로 발사된다

### 구현 내용
- 스페이스바로 와이어 수직 발사
- 와이어가 천장에 닿으면 제거
- 와이어가 존재하는 동안 추가 발사 불가 (1발 제한)

### 고객 확인 포인트
- 스페이스바를 누르면 캐릭터 위로 와이어가 발사되는가?
- 와이어가 천장에 닿으면 사라지는가?
- 와이어가 있는 동안 스페이스바를 눌러도 추가 발사가 안 되는가?

---

## Phase 5. 공(버블) 등장 및 바운스 물리

**목표**: 공이 화면 안에서 자연스럽게 튀어다닌다

### 구현 내용
- 대(Large) 공 1개 등장
- 포물선을 그리며 바닥/벽/천장 반사
- 공의 크기별 렌더링

### 고객 확인 포인트
- 공이 화면에 나타나는가?
- 공이 벽과 바닥에서 자연스럽게 튀는가?
- 공이 화면 밖으로 벗어나지 않는가?

---

## Phase 6. 와이어-공 충돌 및 분열

**목표**: 와이어가 공에 맞으면 공이 분열된다

### 구현 내용
- 와이어-공 충돌 판정
- 대 → 중×2, 중 → 소×2, 소 → 제거

### 고객 확인 포인트
- 와이어가 대(Large) 공에 맞으면 중(Medium) 공 2개가 생기는가?
- 중(Medium) 공에 맞으면 소(Small) 공 2개가 생기는가?
- 소(Small) 공에 맞으면 공이 사라지는가?

---

## Phase 7. 플레이어-공 충돌 (사망)

**목표**: 공에 닿으면 플레이어가 사망한다

### 구현 내용
- 플레이어-공 충돌 판정
- 충돌 시 게임 정지 및 "GAME OVER" 텍스트 표시

### 고객 확인 포인트
- 공에 닿으면 게임이 멈추는가?
- 화면에 게임오버 표시가 나오는가?

---

## Phase 8. 타이머 및 점수

**목표**: 남은 시간과 점수가 화면에 표시된다

### 구현 내용
- 상단 HUD: 제한 시간 카운트다운, 점수 표시
- 공 제거 시 크기에 따른 점수 획득
- 시간 초과 시 게임오버

### 고객 확인 포인트
- 화면 상단에 남은 시간이 줄어드는가?
- 공을 제거하면 점수가 올라가는가?
- 시간이 0이 되면 게임오버가 되는가?

---

## Phase 9. 스테이지 클리어 판정

**목표**: 모든 공을 제거하면 클리어된다

### 구현 내용
- 화면 내 공이 모두 제거되면 클리어 판정
- "STAGE CLEAR" 텍스트 표시 후 정지

### 고객 확인 포인트
- 공을 모두 없애면 클리어 메시지가 나오는가?
- 클리어 후 게임이 정지되는가?

---

## Phase 10. 블럭 시스템

**목표**: 블럭이 화면에 배치되고 공이 블럭 위에서 튄다

### 구현 내용
- 블럭 렌더링 (파괴 불가)
- 공이 블럭 위면에서 반사
- 블럭은 플레이어보다 높은 위치에만 배치

### 고객 확인 포인트
- 화면에 블럭이 보이는가?
- 공이 블럭에 부딪히면 위로 튀는가?
- 플레이어가 블럭을 통과할 수 있는가?

---

## Phase 11. Stage 1-1 완성

**목표**: Stage 1-1이 정식 스테이지로 플레이 가능하다

### 구현 내용
- Stage 1-1 공/블럭 배치 확정 (대 공 1개, 블럭 없음)
- 스테이지 번호 표시

### 고객 확인 포인트
- Stage 1-1 화면에 스테이지 번호가 표시되는가?
- 공 배치와 난이도가 적절한가?
- 클리어/게임오버 흐름이 정상 동작하는가?

---

## Phase 12. Stage 1-2 / 1-3 추가

**목표**: Mission 1의 3개 스테이지를 순서대로 플레이할 수 있다

### 구현 내용
- Stage 1-2: 대 1개 + 중 1개, 블럭 1~2개
- Stage 1-3: 대 2개, 블럭 2~3개
- 스테이지 클리어 후 다음 스테이지 자동 전환

### 고객 확인 포인트
- 1-1 클리어 후 1-2로 넘어가는가?
- 각 스테이지마다 공과 블럭 구성이 다른가?
- 1-3까지 클리어하면 미션 종료 화면이 나오는가?

---

## Phase 13. 게임오버 / 클리어 화면

**목표**: 게임오버와 Mission 클리어 화면이 완성된다

### 구현 내용
- 게임오버 화면: 최종 점수 + 재시작 버튼 + 메인으로 버튼
- Mission 1 클리어 화면: 최종 점수 표시 + 메인으로 버튼

### 고객 확인 포인트
- 게임오버 화면에서 재시작이 되는가?
- 게임오버 화면에서 메인으로 돌아가는가?
- Mission 클리어 화면에서 메인으로 돌아가는가?

---

## Phase 14. 전체 흐름 연결 및 완성

**목표**: 메인 화면부터 종료까지 전체 흐름이 끊김 없이 동작한다

### 구현 내용
- 메인 → 게임 → 클리어/게임오버 → 메인 전체 흐름 검증
- UI 통일 및 전반적인 완성도 정돈

### 고객 확인 포인트
- 처음부터 끝까지 한 번의 플레이가 자연스럽게 이어지는가?
- 모든 버튼과 전환이 의도대로 동작하는가?
- 전체적인 UI가 일관성 있게 보이는가?
